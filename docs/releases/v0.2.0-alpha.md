## MORPHIA v0.2.0-alpha — Operations Intelligence Interface

The MVP proved the engine works. v0.2 makes the thesis *visible* within 10 seconds of seeing the interface.

Previous version looked like a generic CRUD dashboard. This version is a security-operations control plane that makes authorization, scope validation, human approval, independent worker verification, evidence provenance, and auditability first-class parts of the user experience.

### What changed

**Operations Canvas (`/operations`) — new primary interface:**
- High-density layout: Scope/Authorization left, Execution Graph center, Evidence/Findings/Approvals right, live Audit stream bottom
- Answers in one screen: authorized targets, exclusions, active runs, pending human decisions, completed, blocked, latest evidence/finding, recent governance events
- Small metrics strip only, not dominant; thesis footer: Scope before execution · Evidence before conclusions · Humans before consequential actions

**Execution Graph:**
- Interactive pipeline TARGET → SCOPE VALIDATION → PLANNING → HUMAN APPROVAL → QUEUE → WORKER REVALIDATION → EXECUTION → EVIDENCE → FINDING → REPORT
- States pending/active/passed/blocked/failed/awaiting, derived from live run data
- Click node for timestamp, actor, reason, target, relevant scope rule, provider, audit event
- Vertical timeline on narrow screens

**Authorization Boundary / Scope Policy:**
- Split AUTHORIZED / EXCLUDED with counts, patterns, types
- Live policy evaluator: type a target, see ALLOW/DENY with matched rule, dual enforcement (API + worker), execution prevented/permitted, reason recorded, audit emitted
- Engagement authorization basis displayed

**Human Approval Gate:**
- Consequential workspace: Execution paused — human authorization required
- Shows target, engagement, plan, rationale, expected result, authorization basis, matched scope rules, exclusions, provider, affected run, timestamp, audit history
- Approve / Reject / Cancel with justification (audited); communicates that agent cannot simply continue

**Evidence Provenance:**
- Lineage RUN → STEP → ARTIFACT → HASH → VERIFICATION → FINDING → REPORT
- Each artifact shows ID (abbreviated, copyable), capture time, run/step, MIME, SHA-256 (full + truncated with copy), integrity verified, verification status, provenance, linked findings
- Investigator can trace finding → evidence → step → run

**Finding Workspace:**
- Split-pane: list + detail, severity/CWE/confidence/asset, linked evidence, verification history, remediation, audit, report linkage
- Evidence immediately beside finding, not behind five tabs

**Report Workflow:**
- Finding → Verified Finding → Report flow visible
- Report shows included findings, evidence relationships, status, export formats (Markdown/HTML/JSON — no fake PDF), creation/finalization events

**Audit / Governance Stream:**
- Real-time operational stream with actual events/timestamps, filtered by authorization/execution/human/evidence/finding/report/system
- Top live stream + full table with pagination, read-only, append-only

**Design system:**
- Restrained, dense, technical, modern, distinctive — not SaaS template, not cyberpunk, not terminal cosplay
- Borders/spacing/typography over gradients/cards; mono for hashes/IDs/targets/timestamps, normal UI for explanations; semantic colors for pass/denied/attention/active
- Contrast/accessibility, reduced-motion, keyboard nav, focus states

**Demo & seeded state:**
- Seeded workspace now has authorized engagement, allowed scope, excluded scope, completed run, awaiting-approval run, blocked run, evidence with hash, verified finding, report, audit history — all clearly synthetic
- `./scripts/demo.sh` still proves live allowed + denied paths

### Preserved guarantees
- No backend rewrite for aesthetics; all security controls intact (CSRF, auth, RBAC, scope enforcement twice, human approval, worker revalidation, SHA-256, audit)
- No fake metrics, fake scanning, or fake capabilities
- Existing tests continue passing; new tests for operations intelligence added

### Verification

### Limitations (still)
- Single-tenant demo posture, no tenant/role UI
- Approver ≠ creator not enforced
- Worker executes LLM step, not real tools; SSRF/magic-byte checks not implemented; no prod manifests
- Provider selection process-wide, not per-run
