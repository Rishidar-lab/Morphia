# MORPHIA v0.2.1 — Hosted MVP

**Branch:** `release/morphia-hosted-mvp`
**Commits:** `987a0c1` (security hardening + production deploy) through
`dafddde` (deployment-path and test-suite fixes)
**Date:** 2026-09-04 to 2026-09-05

This release note exists because the `987a0c1` commit message referenced a
`docs/HOSTED_MVP_RELEASE.md` that was never actually created — a small,
real example of the same "described but not delivered" pattern this
project's audits keep finding elsewhere. This file is that record, written
after the fact and checked against what's actually in the repository.

## What shipped in `987a0c1`

Closes gaps G1–G8 tracked in `docs/mvp-gap-analysis.md`:

- Self-approval requires a written justification (≥10 chars) and is
  audit-flagged, rather than silently allowed (G1).
- SSRF / cloud-metadata / DNS-rebinding hardening in the new
  `apps/api/app/services/target_safety.py`, enforced at both scope-rule
  creation and execution time (G2).
- Evidence upload validation: size cap, magic-byte sniffing against the
  declared content type, filename sanitization (G3).
- Production secret validator: `SECRET_KEY`/`WORKER_AUTH_SECRET` must be
  real generated values (not placeholders) when `ENVIRONMENT=production`,
  checked at startup (G4).
- Baseline + production-only (CSP/HSTS) security headers (G5).
- The previously-fake Settings page replaced with a real
  `GET /api/v1/system/status`-backed System Status page (G6).
- Responsive drawer navigation under the `lg` breakpoint (G7).
- `docker-compose.prod.yml` + `infra/caddy/Caddyfile`: internal-only
  network for db/redis/api/worker, no bind mounts, a one-shot `migrate`
  service gating API startup (G8).

## What this session (2026-09-05) found and fixed on top of it

Full detail in [`docs/qa/BUG_REPORTS.md`](../qa/BUG_REPORTS.md):

- **BUG-001 (critical):** the dev Compose file's web service was left
  pointing at port 5173 after the Dockerfile was repurposed to serve a
  production build on port 3000 — `docker compose up`, the README's own
  Quick Start command, produced an unreachable web UI. Fixed by splitting
  the Dockerfile into a `dev` build target.
- **BUG-002 (high):** `docker-compose.prod.yml` hardcoded an absolute
  developer filesystem path for the Caddy config, breaking on any other
  machine. Fixed to a path relative to the Compose file.
- **BUG-003 (medium, test defect):** the Playwright `addScopeRule()`
  helper waited on a hardcoded engagement name that didn't match every
  test's setup, and had previously been misdiagnosed as a backend
  session race. Fixed by parameterizing the wait.
- **BUG-004 (low, docs):** the Caddyfile documented a `DEPLOY_MODE=direct`
  TLS mode that was never implemented. Comment corrected to describe only
  the implemented `tunnel` mode.
