## MORPHIA v0.1.0-mvp

First demonstrable, reproducible milestone. The full human-in-the-loop journey
works end to end against a live stack and is verified by service-backed
integration tests and a Playwright browser suite.

### The journey

`register → sign in → project → authorized engagement → allowed scope → run +
plan → review → approve → worker executes (mock provider, synthetic target) →
step captured → evidence → finding → report → audit trail` — plus the
**scope-denied path**: an out-of-scope target is refused by the worker's
independent scope check and the run fails with the reason recorded.

Reproduce it:

```bash
git clone https://github.com/Rishidar-lab/Morphia.git && cd Morphia
make demo
```

### What's in this release

- One-command demo (`make demo` / `scripts/demo.sh`) with a synthetic local
  target, a seeded workspace, and a live allowed/denied scope proof
- React SPA that actually works: CSRF-aware API client, auth guard,
  registration, a run-detail page with plan / step results / event timeline /
  evidence and stage-appropriate approval & transition controls, live-polling
  while the worker runs
- Cross-project API endpoints for the dashboard, evidence, findings, reports,
  and the audit log
- Auth rate limiting applied; audit rows for auth, project/engagement creation,
  and approvals
- CI: Python / worker / frontend quality gates, Docker build, a service-backed
  integration job, a Playwright E2E job (report uploaded as an artifact),
  secret scanning
- Docs: gap analysis, verification matrix, architecture SVG, portfolio copy,
  and a full demo recording kit

### Verified

60 API + 8 worker + 37 web unit tests · 4 live Playwright tests · ruff / ruff
format / mypy / vitest / vite build — all green. Evidence:
[`docs/mvp-verification.md`](docs/mvp-verification.md).

### Known limitations

MVP / alpha. Not addressed yet: separation-of-duties on approvals (a run's
creator can approve their own run), SSRF deny-list in the scope validator,
magic-byte validation on evidence upload, production deployment manifests, a
verified backup/restore drill, and an organization/tenant model. Full list in
the README.

### Quick start

```bash
cp .env.example .env       # set SECRET_KEY, WORKER_AUTH_SECRET, SEED_ADMIN_PASSWORD
docker compose up -d --build
docker compose exec -w /app/apps/api api alembic upgrade head
docker compose exec api python -m app.seed
# open http://localhost:5173
```
